# P0 research evidence

Primary sources accessed November 6, 2026. The source rules below inform the checks. OutcomeLab's rejection policy is intentionally narrower than general HTTP interoperability.

| Source and revision | Relevant rule or boundary | Test or disposition |
| --- | --- | --- |
| [RFC 9110, June 2022, §§ 8.3–8.4 and 9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html) | Content coding determines how to interpret the representation. Senders must list applied codings. Identity is reserved for negotiation and should generally be omitted from Content-Encoding. Method semantics alone do not prove an application effect. | H03–H04 and H17. OutcomeLab accepts an absent coding or one identity token for compatibility, and rejects other codings instead of decoding them. It does not retry uncertain writes. |
| [RFC 9112, June 2022, §§ 5.1–5.2 and 6.3](https://www.rfc-editor.org/rfc/rfc9112.html) | HTTP field syntax and message framing distinguish valid fields from malformed or ambiguous messages. The RFC describes handling of obsolete folding by recipients. | H02, H05–H07, H12–H14, H18–H20. OutcomeLab rejects parser defects, folded fields, disallowed controls, and ambiguous length/transfer framing. This is a verifier policy, not a general HTTP conformance claim. |
| [Python 3.12 http.client](https://docs.python.org/3.12/library/http.client.html) and [Python 3.11 parser defects](https://docs.python.org/3.11/library/email.errors.html) | An HTTP message exposes parsed headers. The email parser can report a missing separator defect for a non-header line while returning previously parsed fields. | H02. Wire tests exercise the actual client and preserve redacted diagnostic categories. |
| [RFC 9457, July 2023](https://www.rfc-editor.org/rfc/rfc9457.html) | Problem Details provides an optional structured error representation. | Future contract error assertions. P0 retains the existing JSON media-type policy. |
| [SQLite URI modes](https://sqlite.org/uri.html) and [WAL](https://sqlite.org/wal.html) | URI mode=ro opens read-only. WAL has additional read-only and sidecar conditions. | D07–D10. P0 retains the local rollback-journal witness and refuses WAL. |
| [OWASP API Security Top 10, 2023](https://api-security.owasp.org/editions/2023/en/0x11-t10/) | Object, property, and function authorization and unsafe consumption are distinct risks. | Future authorized multi-actor tests. P0 is a transport fix, not an authorization assessment. |
| [Hypothesis stateful tests](https://hypothesis.readthedocs.io/en/latest/stateful.html) and [Schemathesis stateful testing](https://schemathesis.readthedocs.io/en/stable/explanations/stateful/) | Existing tools generate operation sequences and can expose invariant violations. | Consider interoperability after the deterministic oracle is stable. No new P0 dependency. |
| [Docker Testcontainers Python guide](https://docs.docker.com/guides/testcontainers-python-getting-started/) | Disposable database containers can support real integration tests. | Future PostgreSQL adapter gate, outside P0. |
| [MCP tools, 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) | Tool annotations are metadata and untrusted servers' annotations cannot establish safe behavior. | A future adapter must use approved execution and independent readback. No MCP feature in P0. |
